RUNTIME AND COMMANDS
Use Node 22.18+ in the 22.x line with npm. Workspace .tools/ contains Node 22.23.3,
used for integration; it is a development install, not a shipped runtime. The
integrated backend/deployment uses Python 3.14. See the root README.txt.

Inside frontend/:
  npm ci                      install exact package-lock.json dependencies
  npm run dev                 Vite development server, localhost:5173
  npm test                    Node runner: 115 passing tests
  npm run build               tsc -b + Vite production build into dist/: passing
  npm run lint                oxlint: 0 errors, 9 warnings in current build
  npm run capture-fixtures    explicitly refresh saved examples from an API

From the root:
  npm run build
  .venv/bin/python -m uvicorn app:app --host 127.0.0.1 --port 8000

Root build runs npm ci/build in frontend/. app.py serves frontend/dist/ and /api
on one origin. Recorded graph checks used this setup on port 18800. Native commands
and lockfiles above are the portable setup, not the workspace-installed .tools/.

LIVE AND SAVED-EXAMPLE MODES
  Development, VITE_API_BASE_URL empty: explicit manifest-listed fixture replay.
  Production, VITE_API_BASE_URL empty: live same-origin API.
  VITE_API_BASE_URL=/: live same-origin API.
  VITE_API_BASE_URL=http://127.0.0.1:8000: live local development API.
  VITE_API_BASE_URL=https://<public-api>: live split hosting; configure backend CORS.

To develop against the API, inside frontend/:
  VITE_API_BASE_URL=http://127.0.0.1:8000 npm run dev

The transport picks mode; components share a typed contract. Saved-example mode
only answers listed requests. Live failures show errors and Retry, never saved
data. Production calls the real server. Vite configuration is public; provider
keys belong only in backend/server secrets.

WHAT IS BUILT
1. Search/route discovery: covered disease/gene/phenotype/organization queries,
   disease choice/shortcuts, natural-history explanation and empty/error states.
   Recorded routes show source, review/origin and partner routes. Suggested disease
   connections stay qualified; resources without matching bundles stay unassessed.

2. Research map: d3-force/SVG with crisp HTML labels, focused/explore, deterministic
   settled layout, staged node births, eased camera focus, gold multi-step recorded
   route trace, portrait reflow, pan/drag/zoom/fit/reset, legend and accessible list.
   Hover/selection exposes relationship details. Anchor follows the actual selected
   assessment; prior selection/trace clears when its resource changes. Source hiding
   fades citing links/source without moving or erasing records. Pause freezes trace
   progress; native and product reduced motion suppress animation while interactions
   remain available. Entity shape/hue and solid/dashed/dotted review/origin styling
   remain distinct: pending edges stay pending and inferred links remain inferred.

3. Evidence: outcome/tally, source-dependence test, actual changed checks, questions
   disclosing support/gaps, public contacts, source/version context and pinned brief
   action. Patient/simple folds depth; doctor/expert exposes more provenance for
   the same records. Only an exact current hidden-list response is current.

4. Brief: exact assessment after-state, supported/open checks, differences, concrete
   next questions, public collaborator route, editable draft, sources/exclusions
   and boundaries. Copy, text download and print/PDF presentation are implemented;
   messages are reviewable artifacts and are never automatically sent.

5. AI: research leads, question assistant, view explanation and paper-excerpt import.
   POST /api/ai/discover takes disease_id/goal_id; POST /api/ai/ask takes assessment_id,
   withdrawn_source_ids, question and patient/expert mode. /api/ai/explain and
   /api/ai/extract are wired. Requests are explicit, with model and live/cached
   provenance; changing assessment/source state invalidates its old answer. New
   hypotheses/extractions remain pending/not imported. Genuine Claude Q&A, extraction
   and explanations work. Genuine live discovery passed with two pending leads;
   local browser replay preserves truthful cached labels. Failures are visible;
   no automatic paid retries,
   fake successful answers or live-to-fixture fallback occur.

6. Product shell: real patient/expert, text size/motion preferences, guide and public
   contact routes; explicitly local profile preview behind signup/login/account,
   and booking/discussion preview. No cloud authentication, booked appointment or
   sent outreach is performed. These preview boundaries are visible.

7. /impact-pilot.html: actual-timing page, initially empty. Records wall/active time,
   source/task/constraint metadata, six quality checks, reviewer/artifact references,
   failures, CSV/JSON exports and eligible matched-pair ratios. Actual two-teammate
   reversed-order measurements remain required. Controls record human review;
   they do not judge brief correctness or generate impact results.

MODEL AND SCIENCE BOUNDARIES
Active AI is existing trained Claude Sonnet 4.6, not a newly trained graph model
or calibrated biomedical predictor. Schema/source binding constrains citations
and recorded state, not semantic medical truth. Published STXBP1/SYNGAP1 connection
is a known validation example; SCN2A proposed fit is unknown. Related disease does
not approve resource/treatment transfer. Model hypotheses need review.
