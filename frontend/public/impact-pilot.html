How much time does preparing a useful brief actually take?

Compare manual research with RareBridge using the same frozen sources, task, and fictional local assumptions. A completed run must pass the quality checklist. This page records real observations; it contains no sample timing results.

Measure brief preparation only. A faster draft does not establish faster expert approval, study launch, treatment development, or clinical benefit. Do not enter patient information. Use anonymous participant and reviewer codes.

Run the pilot fairly
  1. Freeze the source pack: save the exact pages/PDF versions or record their version and hash. Give both methods the same material and fictional constraints. The links below are starting sources, not an automatically frozen pack.
  2. Use at least two participants if possible. Participant A does manual then app; participant B does app then manual. Record familiarity, training, and order. A one-person result must be labelled as such.
  3. Manual: use the source pack, browser, and a blank editor without RareBridge. App: use RareBridge with the same pack and inspect its evidence. Record source inspection, revisions, and checklist review within the timed task.
  4. Start when the participant receives the task. Pause active work only for unrelated interruptions; wall time continues. Finish only when a reviewer has checked all six criteria. Record failed and incomplete attempts too.
  5. Keep the anonymous brief artifacts for quality review. Review without knowing the method when practical. Export the full log and report raw times, quality, failures, sample size, and order limitations.

3. Inspect the measured result

    The ratio is manual elapsed wall time ÷ app elapsed wall time for successful matched pairs only. A value below 1 means the app took longer. Participants, cycle, source pack, code snapshot, exact task, fictional constraints, and familiarity must match; order must be reversed within the pair. Duplicate attempts in one method/cycle make that group ineligible. Active times, failures, and quality notes remain in the full log.
