  from rarebridge.ai.service import (

  )

  capabilities() -> dict
  await extract_source(payload: dict) -> dict
  await explain_assessment(assessment: dict, sources: dict) -> dict

An explanation uses the actual deterministic assessment after withdrawal.
Additional message/provenance validation helpers may be exposed by the module;
the calls above are the stable required integration interface.
Capabilities include ai_extraction, ai_explanation, provider, mode, model,
api_key_configured, can_attempt_live, matching_cache_required and

configured/cache availability, not proof that a live provider call succeeded.
Copy the two AI booleans dynamically into /api/health capabilities; optional

EXTRACTION INPUT AND ROUTE
Optional POST /api/ai/extract request:
  {
    "source_id": "canonical identifier or URL identifier",
    "title": "source title",
    "url": "https://public-source.example/path",
    "published_on": "YYYY-MM-DD or null",
    "text": "Public abstract or supplied source excerpt"
  }

Pass the request dictionary to await extract_source(payload). The lead service
validates the source metadata and returned extraction against the shared schema
and grounding checks. Response is a source-linked candidate graph preview with
pending review status and recorded generation/provenance metadata. Use the
response structure supplied by the implementation; do not reshape graph IDs or
discard source quotes/metadata. The shared shape is
handoffs/contracts/extraction.schema.json.
Input text is evidence data, not instructions that can change the task.
The extraction preview does not enter the reviewed graph or assessment bundles.
The response includes graph_preview in the graph-response shape; Saanvi can
render that pending preview without reconstructing endpoints. Known entity nodes
referenced by a claim are included even if the model did not repeat their metadata.
Preview provenance identifies a caller-supplied excerpt and an extracted_at
timestamp; it does not claim the service fetched the publication at that time.
An exact quote from the supplied excerpt can establish extraction grounding;
it does not establish that the quoted scientific claim is true.

EXPLANATION INPUT AND ROUTE
Optional POST /api/ai/explain request:
  {"assessment_id": "framework-for-syngap1", "withdrawn_source_ids": []}

1. Resolve and validate the bundle using the normal assessment code.
2. assessment = assess(bundle, request.withdrawn_source_ids)
3. explanation = await explain_assessment(assessment, bundle["sources"])
4. Return the handoff envelope expected by the frontend.

If the curated bundle records proposed_use, target_subgroup,
documented_differences or assumptions, copy those fields into the assessment
after result BEFORE calling the AI service, displaying it or building a brief.
The foundation rule engine does not copy every optional bundle field itself.
Keep them recorded context; do not manufacture evidence for them. The service
preserves these fields in its explanation context, and its assessment fingerprint
binds the generated draft to that exact current after state.

Never generate from the pre-withdrawal result when the user has hidden a source.
For /api/assessments/evaluate, preserve before, after, changed_checks, sources,
coverage and contacts. If explanations are included, attach an explanation of
after. Generation must not modify any deterministic check, outcome, evidence,
contact, access condition or collaborator role.

Baseline Explanation fields from rarebridge.handoff.v1:
  generation_mode: "none" | "live" | "cached"
  text: string | null
  cited_source_ids: array of canonical IDs
  model: string | null
Additional provenance/message fields may be retained; do not relabel cached as
live or a deterministic fallback as an AI response. A message is a draft for
review. The service does not email anybody or infer private contact details.

ERROR WIRING
AIServiceError provides code, status_code and to_dict() returning the handoff
error envelope {schema_version,error:{code,message,details}}. Use status_code
for the HTTP response and preserve code/message/details:

  try:
      result = await extract_source(payload)
  except AIServiceError as exc:
      return JSONResponse(status_code=exc.status_code, content=exc.to_dict())

Import JSONResponse from the backend's response framework. Do not catch a
provider/validation failure and return a successful fixture response instead.
When the optional explanation inside an assessment response cannot generate,
the backend can retain the deterministic assessment with Explanation generation
mode none, text null, cited_source_ids=[], model=null and an explicit AI error
field/notice understood by the client. A dedicated AI route returns the error.
Unknown assessment/withdrawal IDs remain the existing 404/422 backend errors.
The service distinguishes upstream_quota_exhausted (credits/spend/usage limit)
from upstream_rate_limited. A safe provider_code may identify the documented
billing cause. Do not keep retrying a credit balance or spend-limit failure.

GENUINE CACHE AND PROVENANCE
The service stores successful real provider responses. Cache identity includes
the input/source hash, prompt/schema versions, provider, model and assessment state,
including withdrawn sources. Never reuse a before-withdrawal explanation as an
after-withdrawal explanation. Matching content can be replayed as cached only.
OpenAI provenance uses provider=openai and a resp_ response identifier; Anthropic
uses provider=anthropic and a msg_ response identifier. Do not reinterpret one
provider's output as the other's or reuse a cache across providers/models.
Keep model/provider response IDs, request/source hashes and generation labels
as supplied. Do not expose API keys or authorization headers in provenance.
Synthetic outputs used in tests remain test fixtures, not runtime model evidence.

  python3 -m unittest discover -s rarebridge/ai/tests -p 'test_*.py' -v

--mode live|auto|cache|off overrides configuration for a CLI run. extract accepts
--preview PATH to save the pending graph preview. brief accepts --with-ai to
request generation, or --response PATH instead of --bundle to use the exact
assessment API response currently displayed. Withdrawal IDs can be repeated.
The default brief uses deterministic facts and does not claim AI generation.
smoke performs actual extraction, a SYNGAP1 explanation and a withdrawn-source
explanation; it saves previews, briefs and a run summary. Its cache-mode replay
must use matching genuine responses. No SDK is required: transport is standard-
library HTTPS against the selected OpenAI Responses or Anthropic Messages API.
doctor/tests do not prove a live integration. Run the genuine live smoke with
a configured key, then its cache replay before demo recording. Configuration
alone does not establish that generation passed; use the verification record.
